\## Реализовано



\### Специализации



Поддержаны 6 специализаций:



\- Backend

\- Frontend

\- Mobile

\- Data

\- DevOps

\- QA



Для каждой специализации используется собственный пул заданий.



Кандидат может иметь несколько специализаций независимо друг от друга.



\### CAT / IRT



Реализована адаптивная система тестирования:



\- генерация задания из `template\_id + seed`;

\- детерминированная генерация;

\- 2PL IRT;

\- расчёт `theta`;

\- расчёт стандартной ошибки `SE`;

\- выбор следующего задания по максимальной Fisher information;

\- остановка при `SE < 0.3` или после 15 заданий;

\- минимум 8 заданий;

\- защита от повторного использования seed для кандидата.



\### Грейды



Диапазоны:



\- Junior: `theta < -0.5`

\- Middle: `-0.5 <= theta < 0.7`

\- Senior: `0.7 <= theta < 1.8`

\- Lead: `theta >= 1.8`



Если результат выше заявленного грейда:



\- заявленный грейд автоматически не повышается;

\- возвращается `recommended\_grade` со следующим уровнем;

\- кандидат может самостоятельно согласиться на следующий грейд.



Если точность результата недостаточна (`SE > 0.45`), грейд не подтверждается.

\## Ручное тестирование



Проверены сценарии Backend и Frontend.



Пример результата:



\- заявленный грейд: Middle

\- `theta = 2.43`

\- `SE = 0.28`

\- подтверждённый грейд: отсутствует

\- рекомендация: Senior



Это соответствует правилам: результат выше диапазона Middle не повышает грейд автоматически, а предлагает следующий уровень.



Также проверена обработка уже завершённого теста.



\## Исправленный баг



Была обнаружена ошибка в логике определения грейда:



результат выше диапазона заявленного грейда ранее мог ошибочно возвращать заявленный грейд как подтверждённый.



Исправлено:



\- результат внутри диапазона → подтверждение заявленного грейда;

\- результат выше диапазона → `recommended\_grade`;

\- результат ниже диапазона → возможность пройти тест на уровень ниже;

\- при `SE > 0.45` → результат недостаточно точный для подтверждения.



Исправление внесено в:



\- `backend/app/api/testing.py`

\- `backend/app/schemas/testing.py`

\- `frontend/src/main.tsx`



После изменения API-контейнер пересобран, Python syntax check пройден, frontend пересобран.
